# Widget constructor oracle: third inactive checkpoint

The bounded host instruction oracle now rejects mismatched allocation/constructor owners unless the currently executing selected method has an explicitly validated direct-parent adapter. The exact initial oracle source is preserved here; it is not active in project/. A host adapter constructs the compile-only child stub and does not prove that Android ART permits the original constructor form.

All 16 synthetic constructor conformance cases passed. They cover ordinary same-owner construction, unconfigured mismatch rejection, exact method/type/owner/signature/occurrence binding, concrete-child/direct-parent requirements, invalid invoke kind, rule duplication and late configuration. The assembled 744-byte synthetic fixture and exact executed classes are preserved with command logs.

A broader regression was then attempted over the existing 1,240-body candidate. Compilation and primitive/engine conformance passed. The UI numeric conformance itself ran, but the new launcher incorrectly required a static oracle field: that suite keeps its oracle in a local variable. The launcher exited with "No executed oracle instances inspected" before the five application suites began. This is retained as a failed regression attempt, not a pass or an application mismatch. The launcher will be corrected narrowly and the actual existing-method suites rerun in a separate report directory.

The full original Widget body has not passed its behavior proof at this checkpoint. The concurrently developed first Widget study also exposed the previously unsupported three-register AND_INT operation; that actual study is preserved by its own checkpoint. Further opcode support and tests will be separate changes. No Widget registry, DEX body or candidate APK is activated here.

The host boundary classes required by the synthetic proof are the exact compile-only adapters from inactive Widget checkpoint02 (commit 2a0bfd2f8953222789d86ffb96a24af652f6c6a8). Its archive preserves every compiled dependency. The broader regression uses the earlier combined19ea input pin and signed9108 candidate, with no parent adapter rules for existing methods and a separate report directory. The result records every input and baseline class hash. Earlier pending draft metadata is retained without rewriting it; the closed reports describe the actual later outcome.
