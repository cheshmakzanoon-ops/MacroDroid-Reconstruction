# Closed local AVD retirement

The stopped, software-emulated `MacroDroid_API35_Disposable.avd` directory was retired after `/root` explicitly authorized only that generated directory. The earlier measured Android framework watchdog failure and stop evidence remain at [`local-framework-watchdog-result.json`](../local-framework-watchdog-result.json), [`local-framework-watchdog.log`](../local-framework-watchdog.log) and [`local-runtime-stop.json`](../local-runtime-stop.json). No app was installed on this failed local runtime.

The final receipt records 30 target entries, including 23 regular files, with 857,440,256 allocated bytes before retirement. It preserves the complete file inventory and SHA-256 hashes, two physical `/proc` process inventories, 14 small configuration/log files, and before/after content hashes for 22 retained control files. The retained controls include all three pinned Android installer archives, the JDK archive, Java/Javac/ADB/emulator executables, toolchain metadata, the AVD index, current APKs and selected source/evidence files. All 22 control records match exactly after removal. They are explicit content controls; they do not claim a complete hash scan of every source or report in the workspace.

Neither `/proc` scan observed a live emulator or QEMU process. The process inventory records physical PIDs, namespace PIDs, command names and executable names. Some executable symlinks, including `/proc/1/exe`, are unavailable under the existing permissions; the guard records that fact and checks the readable command name and command-line executable instead. It does not change access controls. The first attempt stopped at that unreadable executable link before inventory or deletion; its exact source, traceback and result remain in `attempt-01-executable-link-permission/`.

The corrected run checked the complete target inventory again immediately before removal. It copied small configuration and modem metadata, plus the kernel pstore log, into `preserved-metadata/` and checked every retained copy against its original SHA-256. The disposable AVD disk/encryption images were removed rather than published. A marker scan of the preserved metadata and log files found no private-key, ADB public-key or GitHub token markers. This is a limited content scan, not a claim that arbitrary sensitive data can always be detected.

Free disk space rose from 566,362,112 to 1,422,479,360 bytes during the recorded operation. Other ongoing workspace work can change subsequent free-space measurements. The installed SDK/JDK, pinned archives, other AVDs, all APK/source/report paths and every `/tmp` build directory were outside the deletion scope. The original AVD index was deliberately retained; this archived generated state is no longer bootable and can be recreated by the pinned setup tools if needed.

`retire_closed_avd.py` is the exact one-use receipt script. Its target is fixed to the authorized absolute path, it rejects a redirected target or a live emulator, and it refuses to overwrite an existing successful receipt. The complete generated evidence is bound by `checkpoint.json`. This cleanup changes no runtime parity result and does not claim a successful local Android boot.
