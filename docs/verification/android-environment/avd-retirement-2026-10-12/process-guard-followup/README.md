# Physical process identity and visibility follow-up

This additive note corrects one field label in the already frozen AVD retirement evidence. In this execution environment, `os.getpid()` returns the current process's PID inside its namespace. The physical PID exposed by the mounted `/proc` is obtained from the `/proc/self` symlink. The retirement script labeled `os.getpid()` as `reader_physical_pid`; both archived guard reports contain the value 5 in that field. That value must be read as the **reader's namespace PID**. The physical reader PID for those earlier invocations was not separately recorded and is not reconstructed here.

The retirement guard's enumerated `processes[].physical_pid` values were read from the actual numeric `/proc` directories, so those entries remain physical process IDs. The guard checked every readable command name and command-line executable for emulator/QEMU identities; it did not compare any entry to the mislabeled reader value or exclude a namespace PID from the scan. The label error therefore did not remove a process from its blocking check. This note does not change the original script, inventory, receipt or deletion record.

The separate bounded availability probe in `availability.json` demonstrates the distinction directly: its namespace PID is 5 and `/proc/self` resolves to physical PID 92681. It enumerated 25 process entries. Twenty-two other processes denied reads of their working directory and open-file directory. The report preserves those `PermissionError` observations. No permission or namespace setting was changed, and this probe deleted no file. It cannot claim complete working-directory or open-file visibility for another cleanup.

Its current work is confined to `session-guard-forward` and `tooling-validation`.
