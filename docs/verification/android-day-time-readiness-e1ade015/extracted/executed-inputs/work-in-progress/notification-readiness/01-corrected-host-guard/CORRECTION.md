# Correction after two independently reproduced verifier defects

The first inactive guard passed its 15 focused tests. The independent review then reproduced a full-report false acceptance by moving the entire original readiness block from command positions 22–34 to positions 0–12. It also reproduced a narrower phase-only false acceptance: two HOME observations had an actual PID-command span of 0.55 seconds, but an extended row wrapper made the apparent span 1.35 seconds. The full original source, positive results, counterexamples, exact restoration and source identities are retained by the independent review. No Android workflow used this guard.

The correction requires finite, chronological, nonoverlapping global command records and requires the denial input to appear uniquely immediately before its readiness block. Ready-span measurement now uses the first ready PID command's start through the final ready PID command's finish. Wrapper time has no readiness credit. The exact span endpoints are included in the policy. Literal integer checks also reject booleans used as a phase schema, accepted-sequence index or gap index.

The existing recorder calculates its timeout before recording the command start, so inferring its allocation timestamp by adding the timeout to that later start can reject an honestly bounded phase. Replay now validates actual command endpoints inside the unchanged ten-second phase and a positive configured timeout no greater than ten seconds. The live recorder's deadline still applies. Full-frame, process and crash checks are unchanged.

The first test version also reused an already modified global ledger between successive boundary faults. The follow-up restores both the phase and ledger before every fault and checks the intended rejection reason. A later-than-first acceptance test now has internally valid forward timings so it reaches the sequence guard.

The corrected production guard's first 21-test attempt retained one test failure: adding a misplaced field to a selected screenshot was already rejected by the existing exact selected-snapshot comparison, before the test's expected readiness-field-count message. The test-only follow-up places that same synthetic extra field on the run object to reach the intended count guard. The earlier snapshot rejection remains unchanged. Both confirmed verifier counterexamples already rejected in that attempt and in the separate independent corrected-source review.

The local overlay filled while the independent source-cache assessment was being preserved. All writers stopped. This corrected stage was then copied byte-for-byte into a separately owned temporary filesystem: 83 inputs, 11,852,112 bytes, with the overlay unchanged. Test temporaries use that separate capacity. Both stages and every closed attempt will be included in the durable checkpoint; no source-cache content was removed to run these controls.
